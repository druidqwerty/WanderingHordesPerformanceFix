# Wandering Hordes Save Trim [B42]

<p align="center"><img src="docs/preview.png" alt="Wandering Hordes Save Trim" width="320"></p>

Дополнение к [Wandering Hordes](https://steamcommunity.com/sharedfiles/filedetails/?id=3759920384) (автор SpaceGamer_R):
не даёт его карте стен раздувать сохранение и подвешивать сервер при каждом сохранении мира.
Сам Wandering Hordes не меняется, его код не копируется; это отдельный Lua-мод.

**Steam Workshop:** https://steamcommunity.com/sharedfiles/filedetails/?id=3829140377 · **Исходный код (MIT):** https://github.com/druidqwerty/WanderingHordesSaveTrim

## Проблема

Wandering Hordes запоминает стены, заборы и воду для каждой клетки, рядом с которой хоть раз был игрок: его
сканеры каждый тик заполняют «карту проходимости» (глобальная таблица ModData `WH_PassabilityGrid_v2`) в радиусе
30 клеток от каждого игрока, и ничего никогда не удаляется. Долгая поездка оставляет за собой полосу шириной
61 клетку. Игра записывает все глобальные ModData в `global_mod_data.bin` при каждом сохранении мира, в главном
потоке сервера, и читает их целиком при каждом запуске.

На нашем кооп-сохранении на двоих:

- карта стен занимала **58 МБ из 76 МБ** `global_mod_data.bin` (36 646 ячеек по 10×10 клеток) и росла с каждой
  поездкой;
- каждое сохранение мира (раз в 5 минут) подвешивало сервер на ~0,3 с; **первое сохранение после запуска — 6,3 с**,
  и игра ставила всех игроков на паузу;
- её загрузка занимала **6,9 с** при каждом запуске сервера, а в памяти она занимала больше 400 МБ кучи Java
  сервера.

Wandering Hordes читает карту только чтобы проверить, не огорожена ли клетка, где вот-вот появится орда (он идёт
вдоль стен до 300 клеток от этой клетки, а она не дальше 75 клеток от игрока), и как быстрый признак воды.
Отсутствующая клетка значит просто «ещё не просканирована»: сканеры заполнят её снова, когда рядом окажется игрок.

## Что делает дополнение

- Раз в 2 минуты (настройка) проходит по карте, по несколько сотен ячеек за тик, и удаляет ячейки 10×10, которые
  дальше 400 клеток (настройка) от всего этого:
  - каждого игрока;
  - места, где каждый игрок вошёл в игру (обычно база, где он вышел в прошлый раз), в том числе пока он в дальней
    поездке;
  - места, где каждого офлайн-игрока видели последний раз (сервер в мультиплеере, помнится 30 дней);
  - каждого убежища (safehouse).
- Рядом с игроками ничего не меняется: 400 клеток покрывают всё, до чего дотягивается проверка забора
  Wandering Hordes от орды, появляющейся рядом с игроком (75 + 300 клеток).
- Вдали Wandering Hordes забывает свою карту стен; когда туда кто-то вернётся, он просканирует место заново, как
  место, где ещё никто не был.
- Ничего не удаляет, если не вокруг кого хранить, и никогда не создаёт и не заменяет таблицу Wandering Hordes.
- Работает на сервере (именно это попадает в сохранение) и в одиночной игре. На клиентах в мультиплеере обрезает
  и их собственную копию в памяти: B42 запускает сканеры Wandering Hordes и там (клиенты её не сохраняют).

## Живой тест

Локальный выделенный сервер и один клиент, Wandering Hordes [Core] + пресет Vanilla+ (наши кооп-настройки), наш
настоящий `global_mod_data.bin` на 76 МБ (58 МБ из них — карта стен), сохранение мира каждую минуту, сценарий
поездки (база, 1,8 км, 3,4 км, база) с принудительными ордами:

| | без дополнения | с дополнением |
|---|---|---|
| Карта стен | 36 646 ячеек, 58 МБ | 4 221 ячейка, 7 МБ |
| `global_mod_data.bin` | 76,1 МБ | 25,0 МБ |
| Подвисание сервера на ModData при каждом сохранении | 0,33–0,43 с (один раз 2,0 с) | 0,10–0,17 с |
| Первое сохранение после запуска (игроки на паузе) | 8,2 с | 0,55 с |

- Первая проверка старой карты на 76 МБ: 9 с, растянутые на 92 тика, около 0,5 мс за тик (максимум 4 мс). Следующие
  проверки: около 1 с, меньше 1 мс за тик. Между проверками — ничего (0,006 мс за тик).
- Перезапуск с обрезанным сохранением: загрузка 0,14 с на тестовом сервере (старый файл на 76 МБ — 0,21–0,30 с).
  Настоящий кооп-сервер грузил старый файл 6,9 с (у него 300+ модов); новое время будет видно в следующей сессии.
- Офлайн-стенд на собственном коде загрузки/сохранения игры: после обрезки куча Java меньше примерно на 433 МБ;
  первое сохранение 4,9 с → 0,23 с, следующие 125 → 40 мс.
- Собственная проверка Wandering Hordes, где может появиться орда (`isSquareSafeForSpawn`, решётка 21×21 вокруг
  базы с шагом 5 клеток), даёт те же ответы с дополнением и без, в том числе после поездок за 1,8 км (2,5 и
  5 минут, несколько проверок за каждую), когда база не убежище: её держит место входа. Орды появлялись как
  обычно. Ошибок Lua нет.
- Изменение настроек админом в идущей игре применилось на следующей проверке (радиус 400 → 150; выключение —
  проверки прекратились).
- Остальные 18 МБ того файла — данные других модов; дополнение трогает только таблицу Wandering Hordes.

## Требования и установка

- Build 42.21+ и [Wandering Hordes](https://steamcommunity.com/sharedfiles/filedetails/?id=3759920384) [Core]
  (с одним из его пресетов, как обычно).
- Одиночная игра: просто включить.
- Мультиплеер: мод должен быть в списке модов сервера: добавьте `WanderingHordesSaveTrim` в `Mods=` (после
  `WanderingHordesCore`) и `3829140377` в `WorkshopItems=`. Подключающиеся игроки получат его из Мастерской
  автоматически.
- Можно добавить в уже идущее сохранение: первая проверка обрежет старую карту (несколько секунд, растянутых на
  тики), файл уменьшится при следующем сохранении мира. Убрать потом тоже безопасно: Wandering Hordes просто снова
  начнёт растить карту.
- Без Java и без ZombieBuddy.

## Настройки

Хост задаёт их для всех: Хост > Управление настройками > Изменить > Песочница > **Wandering Hordes: Save Trim**.
Админ может менять их в идущей игре (Админ > Настройки песочницы); применяются на следующей проверке.

- **Обрезать карту стен Wandering Hordes** (вкл.). Выкл.: как без дополнения.
- **Радиус хранения (клеток)** (400; 100–5000). Меньше = меньше сохранение; огороженное место дальше будет
  просканировано заново, только когда к нему подойдёт игрок.
- **Хранить вокруг места входа** (вкл.).
- **Хранить вокруг офлайн-игроков** (вкл.; сервер в мультиплеере).
- **Хранить вокруг убежищ** (вкл.).
- **Проверять каждые (минут)** (2; 1–60).
- **Отладочный лог** (выкл.): строка о каждой проверке в консоли.

## Работает ли?

В консоли сервера (`console.txt` в одиночной игре) есть строка `[WHSaveTrim] 1.0.0 loaded (server)` (или `(sp)`),
а после первой проверки старого сохранения — строка вида
`[WHSaveTrim] pass 1: 36646 cells checked, 32425 removed (~48.4 MB), 4221 kept (~6.9 MB); keep radius 400 around 1 player(s), 1 join spot(s), 0 offline spot(s), 0 safehouse(s); 92 ticks, 0.50 ms/tick, max 3 ms, 9.1 s`.
`global_mod_data.bin` в папке сохранения уменьшится при следующем сохранении мира.

## Известные ограничения

- Обрезанное место для Wandering Hordes — как место, где ещё никто не был: он сразу сканирует 30 клеток вокруг
  игрока, остальное — по мере того, как игроки там ходят. До этого его проверка забора там может пустить орду
  внутрь большой огороженной территории, которую он ещё не знает (как в любом новом месте). Ваша база хранится
  (место входа, офлайн-место, убежище); другие важные огороженные места сделайте убежищем или увеличьте радиус.
- Место входа — где игрок вошёл в игру; если выйти в другом месте, следующим местом входа будет оно. Надёжнее всего
  базу держит убежище.
- Дополнение трогает только таблицу Wandering Hordes; данные других модов в `global_mod_data.bin` остаются как есть.

## Как это устроено (для моддеров)

- Ключи Wandering Hordes (`WH_Server.lua`): ключ ячейки `gx * 100000 + gy`, где `gx = floor(x / 10)`, ключ клетки
  `x * 100000 + y`, маски NORTH 1, WEST 2, WATER 4, SCANNED 8.
- Проверка идёт `pairs()` по таблице через несколько тиков (`pairs()` в Kahlua работает по снимку ключей, поэтому
  удалять записи по ходу безопасно; ячейки, добавленные за это время, ждут следующей проверки), по 400 ячеек за
  тик; каждая ячейка сравнивается с квадратами (в координатах ячеек) вокруг игроков, мест входа, офлайн-мест и
  убежищ; текущие позиции игроков добавляются каждый тик.
- Свои данные: глобальная ModData `WHSaveTrim`, только на сервере: `spots[имя]` (где видели последний раз) и
  `homes[имя]` (место входа), обновляются раз в 2 с, удаляются через 30 дней без игрока. В одиночной игре и на
  клиентах места входа за сессию хранятся в памяти.
- Настройки читаются из `SandboxVars.WHSaveTrim` при каждой проверке (Enabled — каждый тик).

## Исходники и тесты

- `common/` и `42/` — сам мод (`42/media/lua/server/WanderingHordesSaveTrim/WHSaveTrim.lua`); в zip релиза и в
  Мастерской те же файлы.
- `tools/offline_test.sh`: проверка синтаксиса компилятором Kahlua из игры, затем 93 офлайн-проверки
  (`test/offline`: подменённый API игры; сервер, клиент и одиночная игра) в Lua-машине игры. Нужны JDK и игра:
  `JDK=<jdk>/bin GAME=<папка ProjectZomboid> tools/offline_test.sh`.
- `tools/bench.sh` + `tools/GmdBench.java`: время загрузки/сохранения и цена дополнения за тик на копии настоящего
  `global_mod_data.bin`; `tools/gmd.py`: размеры таблиц в `global_mod_data.bin` и что оставит обрезка.
- `livetest/whlive.py` + `test/WHTrimTest/`: живой тест (выделенный сервер и клиент без Steam, сценарий поездки) и
  его мод-помощник.
- `python tools/build.py --no-install --no-staging`: офлайн-тесты, затем папка мода и zip в `dist/`.
